# Звірка каси за день

Доповнення до встановленого касового обліку V85. V84 normalize_items_calculation_collation і V85 cash_accounts залишаються без змін. Нова міграція — V86.

## Установлення
1. Скопіюйте backend/src і frontend/src у відповідні проєкти зі збереженням структури та заміною файлів. Не видаляйте решту файлів каталогів.
2. Виконайте тести у backend:

```powershell
.\gradlew.bat test --tests "com.example.baget.cash.*" --tests "com.example.baget.finance.*" --tests "com.example.baget.billing.*" --tests "com.example.baget.payroll.*"
```

3. Перезапустіть backend — Flyway застосує V86__cash_reconciliations.sql.
4. Для опублікованого Vue виконайте `npm run build` і замініть збірку; для dev оновіть сторінку.

## Як користуватися
«Каси та рахунки» → потрібна готівкова каса → «Звірити готівку».
Форма показує початковий залишок дня, надходження, вибуття, їх склад і розрахунковий залишок. Початкове введення коштів, якщо зроблено цього дня, показується окремим надходженням, не дублюється в залишку на початок дня.
Перерахуйте готівку, введіть фактичну суму. Якщо є нестача чи надлишок, додайте примітку й натисніть «Зберегти звірку».

- Збереження НЕ змінює ledger_entries, залишок каси або борг клієнта.
- Звірка не закриває день, не блокує касу і не списує нестачу.
- Можна зберегти кілька звірок за день; кожна має незмінні суми, автора, час і примітку.
- Фактичний перерахунок записується лише за поточний день Europe/Kyiv. Для минулого дня можна переглянути облікові підсумки й історію збережених звірок.
- Якщо після відкриття форми пройшла нова проводка, сервер відхилить застарілі суми навіть при незмінному підсумковому залишку. Оновіть форму та перерахуйте гроші.
- При втраті відповіді кнопка «Перевірити / повторити» надсилає той самий запит. Він зберігається в sessionStorage для повернення після оновлення сторінки в тій самій сесії браузера.
- Менеджер звіряє каси дозволених філій. Центральна каса доступна бухгалтеру / адміністратору за вже чинними правами.
- Банківські рахунки та «Кошти в дорозі» не мають кнопки перерахунку готівки й не приймаються API звірки.
- Адміністратору показується остання звірка кожної каси з ненульовою різницею. Вона може бути за попередній день: дата видима. Нова звірка з нульовою різницею прибирає касу зі списку, але всі попередні записи залишаються в історії. Це список останніх спостережень, не процедура затвердження чи списання нестач.

## Наскрізний приклад для перевірки на тестовій базі
1. Каса філії має 1000 грн, центральна — 500 грн.
2. Прийняти аванс 300 грн у касу філії → 1300 грн.
3. Зарахувати 200 грн із цього авансу на рахунок → каса лишається 1300 грн.
4. Передати 800 грн до офісу → філія 500 грн, у дорозі 800 грн, центральна 500 грн.
5. Інший бухгалтер підтверджує отримання → центральна 1300 грн, у дорозі 0 грн.
6. Виплатити 100 грн нарахованої винагороди іншому менеджеру → центральна 1200 грн.
7. Звірка філії: очікується 500, фактично 490, примітка → різниця -10. Залишок каси все ще 500 грн.
8. Повторити запит із тим самим requestKey → другий запис звірки не з'являється.
9. Відкрити звірку, провести нову оплату в іншому вікні та спробувати зберегти стару форму → відмова з проханням оновити дані.

## Виконані перевірки та межі
- 38 ізольованих перевірок реального CashService з підставними Spring/JDBC/JSON API, у тому числі касові передачі, виплата, звірка, повтори, права і відсутність касових проводок при звірці. Перевірена кількість SQL-параметрів виконаних запитів.
- 16 перевірок нового Vue-компонента з імітацією API: пояснення різниці, повтор після збою / перезавантаження, застаріла форма, минулий день.
- 22 регресійні перевірки касового UI та оплати рахунків із імітацією API; компоненти компілюються.
- Окремо перевірено арифметику BigDecimal (філія 500 / центральна 1200), копійки, порожній день і 23/25-годинні дні Europe/Kyiv.
- Запит підсумків перевірений на SQLite-фікстурі для меж дня й ізоляції кас; це не перевірка MySQL.
- Синтаксичний розбір 438 Java-файлів та перевірка синтаксису 37 JavaScript-модулів.
- Додано JUnit CashReconciliationTest для запуску у вашому Gradle-проєкті.

Повний Gradle-прогін, міграція на MySQL, перевірка транзакцій під одночасними запитами та візуальний браузерний тест тут не виконані. Контрольний приклад вище потрібно пройти у вашому середовищі; автоматизовані ізольовані перевірки не замінюють його.
