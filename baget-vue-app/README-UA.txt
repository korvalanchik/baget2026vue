Складська собівартість витрачених матеріалів — V82
Пакет змін поверх V81. Оновіть backend/src, frontend/src; запустіть backend для Flyway V82 та перебудуйте frontend.

Items.Cost залишається розрахунковою вартістю з накладними: звичайні позиції отримують її під час створення замовлення, додаткові позиції доопрацювання — за чинною логікою підготовки доопрацювання.
Нове items.inventory_unit_cost зберігає складську вартість одиниці при фізичному списанні.
Те саме значення, одиниця й час фіксації записуються в inventory_movements.
Знімок виконується одразу після створення руху в тій самій транзакції під блокуванням Parts.
Включено WorkshopService.complete, ProductionService.finalizeProduction, ReworkService.complete.
Списання доопрацювання додає окремі items; попередні рядки не переоцінюються.
Чинна унікальність inventory_movements(order_no,item_no) означає одне списання на рядок. Усереднення між кількома рухами тут не потрібне й не вводиться.
Нульова відома ціна допустима; невідома, від'ємна або ціна в іншій одиниці фіксується як NULL.
Міграція не заповнює минулі списання поточними цінами. Роботи та позиції без додатного списання не оцінюються цим механізмом.
Parts.Cost, прайси продажу, обчислення рахунків та ledger_entries не змінюються.

Майстерня → картка виробу → «Закупівельна вартість списаних матеріалів».
Блок та API доступні лише адміністратору. Для кожного руху показуються кількість, складська ціна, вартість, дата, позиція замовлення та позначка доопрацювання.
Якщо є невідома ціна, загальна сума показується як «Не визначено», а відома частина — окремо. Без рухів оцінка не показується як нуль.
Суми рахуються за зафіксованими рухами, не за поточними Parts чи редагованими планами. Підсумок округлюється до копійок після підсумовування.

Перевірки в цьому середовищі: ESLint, компіляція двох Vue SFC, 6 перевірок із підмінним API, синтаксичний розбір Java та кількість параметрів нових SQL.
Додано ConsumptionCostTest: доступ, сума рухів, невідома/нульова вартість, відсутність рухів, запис знімка.
Повний Gradle/JUnit, реальний MySQL/Flyway та браузер не запускалися.
Локально виконайте: .\gradlew.bat test --tests "com.example.baget.orderproduct.*"

Ручна перевірка: встановіть відому складську вартість → завершіть новий виріб → перевірте items.inventory_unit_cost та блок витрат → проведіть прихід за іншою ціною → упевніться, що історична вартість виробу не змінилася. Перевірте також додаткове списання доопрацювання і матеріал без заданої вартості.
