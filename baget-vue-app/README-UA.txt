Результати роботи — власні філії
Пакет змін поверх V82 та виправлення ReworkServiceTest. Нової міграції немає; потрібна застосована V82.
Оновіть backend/src та frontend/src, перезапустіть backend і перебудуйте frontend.

Меню «Результати роботи» — лише ROLE_ADMIN; сервер також перевіряє роль.
Виберіть період (до 366 календарних днів, включно з кінцевим днем за Europe/Kyiv) та філію. Початковий період — поточний місяць до сьогодні.
Філії списку мають хоча б одне замовлення з commerce_mode=OWN. Звіт відбирає режим із самого замовлення, а не з поточних налаштувань філії.
Кожна картка OrderProduct враховується один раз за першою product_transfers action=ACCEPT,to_location=CUSTOMER. SEND та CANCEL не є видачею. Це кількість карток, не фізичних одиниць усередині картки.
Суми продажу — invoice_products.billed_amount через поточну прив'язку product_invoice_claims до чинного рахунку. Об'єднання рахунків не дублює вироби. Загальні старі рахунки без суми на виріб не розподіляються довільно: сума невідома.
Матеріали — збережена inventory_movements.inventory_unit_cost, лише рухи до першої видачі. Доопрацювання до видачі враховуються. Якщо додатна фактична витрата матеріалу не має руху або його ціни — оцінка неповна. Поточний Parts.Cost/складська ціна не використовуються.
Винагороди — ACCRUAL+CORRECTION за вибраними виробами, включно з пізнішими коригуваннями на момент перегляду. PAYOUT/REVERSAL виплат не віднімаються вдруге. REVIEW блокує повний результат. Якщо нарахувань не було (наприклад, механізм був вимкнений), показується фактично нараховано 0 без застосування поточних ставок заднім числом.
Різниця = продаж - складські матеріали - нарахована винагорода. Це не чистий прибуток: зарплата майстерні, оренда та інші накладні не включені.
За неповних даних загальна різниця не визначається; показуються відомі частини та різниця лише за повністю оціненими картками.
Підсумки охоплюють усі сторінки, список по 50 рядків. Понад 10000 карток за один запит — попросить звузити період/філію, не обрізає підсумок мовчки.

Обмеження першого етапу: це звіт видач, а не чистих продажів після повернень; повторну видачу не рахує повторно. Старі видачі без події приймання не відновлюються зі StatusOrder. Історичні назви філії/артикулу показуються за поточними довідниками. Дані винагород і чинність рахунків можуть змінити результат минулого періоду після коригувань; це не закриття бухгалтерського періоду.
Надходження, аванси, борги та посередники у цей етап не входять. Звіт нічого не записує і не змінює ledger_entries.

Перевірено: 4 виконаних сценарії чистої Java-математики, 7 перевірок Vue з підмінним API, компіляція SFC, ESLint, синтаксис Java. Додано OwnerResultsMathTest і OwnerResultsServiceTest (доступ, межі періоду Europe/Kyiv, підсумки всіх сторінок).
Повний Gradle/JUnit, виконання SQL на MySQL та реальний браузер тут не запускалися.
Локально: .\gradlew.bat test --tests "com.example.baget.reports.*"
Після встановлення звірте один період із відомою видачею: суму рахунку, знімок списання V82, винагороду і підсумкову різницю. Перевірте невідому ціну старого списання — вона не повинна давати хибний повний результат.
