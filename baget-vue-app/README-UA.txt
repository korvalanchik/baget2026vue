CRM: РОБОЧИЙ СПИСОК ТА ІСТОРІЯ ВИДАЧІ

Пакет поверх мобільних карток оплати й видачі. Замініть backend/src та frontend/src у відповідних проєктах. Перезапустіть backend; перебудуйте production frontend. Міграцій немає.

Повністю видані замовлення прибрані зі списку «Замовлення й видача». Частково видані показують невидані вироби. Замовлення в майстерні залишаються. Старі замовлення зі статусом 12 теж виключені.
Нові записи видачі містять номер замовлення та client_product_id (наприклад art-1), а не числовий ID order_products. Це позначення виробу всередині замовлення, не артикул багета.
Старі записи «Номери: [ID]» відображаються з артикулами, якщо request_json зберіг склад видачі й відповідні вироби доступні. Інакше зберігається оригінальний текст. Історичні записи БД не переписуються. Нові записи з артикулами не переформатовуються.

Перевірено: синтаксис Java, ESLint, вибірка на невеликій SQLite-фікстурі (повна/часткова видача, майстерня, старе видане/відкрите замовлення). Повна компіляція Java, Gradle і MySQL тут не виконані.
На ПК: .\gradlew.bat test --tests "com.example.baget.crm.*"
Фронтенд: npm run build
Перевірте повну і часткову видачу, старі записи історії та номер замовлення в них.
