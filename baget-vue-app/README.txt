Відкриття вкладки «Рахунки за виробами»

Скопіюйте backend/src у src бекенду, frontend/src у src фронтенду. Перезапустіть сервер та оновіть сторінку.
Міграцій БД немає.

ProductInvoiceProcessor.options(): нормалізація null-пошуку до порожнього рядка. Початковий GET /api/product-invoices/options більше не викликає q.trim() при q == null.
Пошук платників починається від двох символів; доступ до філій зберігається.
Фронтенд розрізняє помилки GET-завантаження та фінансової операції; для GET показує HTTP-статус, якщо сервер не надав пояснення.

Додано 3 регресійні тести. Java-синтаксис і ESLint перевірені. Gradle/JUnit локально не запускалися: робоча копія містить лише сорси.
Перевірте у своєму проєкті:
.\gradlew.bat test --tests "com.example.baget.billing.*"

Якщо після оновлення проблема залишається, надішліть URL і статус невдалого запиту з Network та відповідний стек помилки сервера. При відкритті послідовно викликаються /options і /ready.
